# DR: 网站基础定价金额试算与案例

Status: implemented

## Problem

每百万单价无法直接回答一组翻译或 coding 用量需要多少钱。用户需要自己填写四项 token，并借助截图比例折算的亿级案例比较模型；累计用量不是单次请求上下文，用户要求试算使用基础定价、忽略上下文阶梯。

## Decision

本决策部分取代 [静态双语定价网站](../implemented/2026-10-12-bilingual-pricing-website.md) 中不提供费用计算器的范围；其单源数据、静态架构、语言货币与发布约定继续生效。

搜索栏旁提供金额试算入口，在右下角打开小型悬浮面板，以两行填写未缓存输入、输出、缓存读取与缓存创建，允许累计用量。悬浮窗不挤占排行榜的纵向空间，用量与计价说明折叠展示。输入单位是实际 token，各项及合计必须是非负安全整数；无效输入显示错误提示并停止出价。缓存用量不重复包含在未缓存输入内。

输入框实时按千位显示逗号，接受带或不带逗号的整数；格式化直接处理字符串，避免超出安全整数时被 Number 提前舍入。编辑保留光标对应的数字位置，逗号旁的退格或删除跳过分隔符并删除相邻数字。非法字符不被吞掉，负数、小数及过大数值仍能显示并触发校验。

`src/lib/calculator.ts` 维护四个可修改案例和费用计算，模型价格继续只来自根目录 JSON。翻译为 100,000,000 输入 / 100,000,000 输出，无缓存。三个 Coding 案例分别为极高缓存 98.5%、高缓存 95%、低缓存 90%；依据用户三张截图的分项比例归一化为四项合计 100,000,000，缓存创建均为 0。极高缓存命中率按缓存读取 /（输入 + 缓存读取 + 缓存创建）计算，标题四舍五入至一位小数。

原始输入 / 输出 / 缓存读取为 `2.3M / 597.7K / 146.1M`、`18.8M / 2.3M / 344.9M`、`11.7M / 565.2K / 99.9M`，使用分项之和（不采用已舍入的图中总计）作分母。向下取整后按最大小数余数补足剩余 token；归一化得到 `1,543,648 / 401,147 / 98,055,205`、`5,136,612 / 628,415 / 94,234,973`、`10,431,043 / 503,899 / 89,065,058`。每项误差小于 1 token。“95%”“90%”保留为用户案例名称，不强行调整实际比例。

面板显示“翻译”“Coding”两个入口。翻译直接填入用量；Coding 打开原生 dialog，列出三个案例及四项用量，选中后填入并关闭。原生 dialog 提供焦点隔离、Escape 关闭和关闭后焦点恢复，也支持点击遮罩关闭。选择状态按当前四项输入匹配，手动修改后取消原案例选中标识。

弹窗用量展示采用 `M`（百万，截取至两位小数）和 `K`（千，截取至一位小数），小于千的数值直接显示，悬停标题和读屏标签保留完整整数。简写仅影响展示，表单填入值、归一化总量及金额计算继续使用原始整数。

试算使用 `activeContainer` 选择当前价格时期，然后只判断该容器根的 `dailySlots`，最终使用当前容器的基础价格或其峰时覆盖。所有上下文 tier 均不用于试算，包括阈值为 0 的 tier；因此亿级累计用量不会触发长上下文单价。金额为四项 `tokens × 每百万单价 / 1,000,000` 相加，求和前不舍入；美元继续按表内汇率换算。原有三层 `resolvePrice` 与完整规则浏览继续遵守数据规范。

价格表在试算开启时增加本次用量的预估金额列及金额升序、降序排序；桌面金额列标题可点击切换方向，并标注当前排序方向。展开模型展示四项适用单价、金额和规则来源。面板和明细明确标注基础定价、忽略上下文阶梯。四项原始单价列保留最低上下文档位语义，说明文字指出它们可能与试算单价不同。

面板显示与试算启用是独立状态。“完成·收起”、标题收起按钮及 Escape 隐藏面板但保留金额列、用量和排序，右下角“编辑用量”重新打开；Coding 弹窗优先处理 Escape。“关闭试算”保留已填用量，移除金额列，并在原排序为任一金额方向时恢复数据顺序。中英文和手机卡片布局均覆盖试算入口、输入及结果。

## Alternatives considered

**每个模型各自填写一份用量。** 会增加重复输入，且对比时容易使用不同用量。共享输入和逐模型结果允许同一场景直接比较。

**占据列表顶部的大面板。** 四项输入和说明会推下主要排行榜。紧凑悬浮窗及独立收起状态保留操作入口和试算结果，用户可随时收起以浏览被覆盖的行。

**用累计量触发完整上下文阶梯。** 1 亿 token 的累计用量无法代表一次请求的上下文，会把不同场景都误判为长上下文。用户明确选择基础定价比较，因此试算主动忽略 tier，只保留日期和峰时规则；真实请求阶梯仍可在详情中查看。

**把案例写入定价 JSON。** 案例属于网站演示，不是模型定价或计费规则。独立源码常量避免新增 Schema 字段或影响原消费者的数据版本。

## Consequences

用户能用同一组用量比较全部模型，展开后可核对选价来源及四项费用。单源价格、基础节点峰时隔离、tier 忽略、零值、小额费用、无效输入、案例总量与截图比例都有测试；功能增加浏览器计算和组件维护成本。

试算是基础定价比较，不模拟多轮会话、跨时段批量请求或模型能力限制，也不据此推断每次请求的上下文或账单。缓存零价格仍不代表支持缓存。日期自动随当前时刻刷新，因此跨定价边界金额会更新，面板显示实际使用的时间。

功能在浏览器完成，不改变价格数据、识别语义或对外 Schema，数据版本和更新时间无需调整。
